| 항목 | 내용 |
| :--- | :--- |
| 시스템명 | **KJ-OMS** (Kumoh-Jeongmil Order Management System) — 수주·납품 관리 Back-office |
| 핵심 문제 | 엑셀 수주·납품대장의 표기 불일치로 **12개월 집계 중 동일 부품 107개가 별도 품목으로 분리 집계** |
| 핵심 해법 | **기준정보(Master Data)** — 품번 12종 × 발주처 8곳 + 표기 규칙(품번·날짜·단위)으로 입력 단계에서 검증·자동 교정 |

| 이번 범위 | 사내 처리 흐름 5단계 중 **1단계 [영업] 수주 관리** (나머지 4개 부서는 확장 슬롯으로만 표시) |

### 사내 처리 흐름 (확장형 구조)

```text
[영업] 수주 접수 ──▶ [생산] 재고·생산 확인 ──▶ [구매] 자재 발주 ──▶ [품질] 출하검사·납품 ──▶ [경영지원] 월말 정산
  수주 관리 ★이번 구현     생산 관리 (Phase 2)      발주 관리 (Phase 3)     품질·출하 관리 (Phase 4)      정산·보고 (Phase 5)
```

- 모든 부서는 **같은 기준정보(품번·발주처·단위)** 를 공유한다. 1단계에서 기준정보를 바로 세워야 2~5단계가 같은 품번으로 연결된다.
- 화면 상단의 「금오정밀 사내 시스템 지도」 스텝 바에 5개 부서를 모두 표시하고, 현재 활성 노드(영업)만 펄스 글로우로 강조한다.

## 2. 목적 (Why)

### 2-1. 현재 문제 — 엑셀 수기 관리

1. 담당자마다 품번·날짜·단위 표기가 다르다 (`KJ-H2201` / `KJH2201` / `kj-h2201`, `1/05` / `26/1/12`, `개` / `EA` / `세트` 혼용).
2. 그 결과 **12개월 집계 중 동일 부품 107개가 별도 품목으로 분리 집계**되었다.
3. 대표 사례 — 같은 부품 `KJ-H2201`이 두 품목으로 쪼개짐:

| 날짜(원본) | 품번(원본) | 수량 | 비고 |
| :---: | :---: | ---: | :--- |
| 1/05 | `KJ-H2201` | 40 | 표준 표기 |
| 1/12 | `KJH2201` | 35 | **하이픈 누락 오표기** |
| 1/20 | `KJ-H2201` | 50 | 표준 표기 |
| 1/27 | `KJH2201` | 22 | **하이픈 누락 오표기** |

| 집계 방식 | 결과 | 판정 |
| :--- | :--- | :---: |
| 기준 없이 집계 | `KJ-H2201` **90개** + `KJH2201` **57개** → 서로 다른 부품 2개 | ❌ 오집계 |
| 표기 규칙 적용 후 집계 | `KJ-H2201` **147개** → 단일 부품 1개 | ✅ 정확 |

4. 승인·변경 이력이 남지 않아 "누가, 언제, 무엇을 고쳤는지" 추적할 수 없다.

### 2-2. 개선 목적

| # | 목적 | 측정 지표 |
| :---: | :--- | :--- |
| P1 | **입력 단계에서 표기 오류 차단** — 기준정보 기반 실시간 검증 | 품번 정규식 불일치 검출률 100% |
| P2 | **동일 부품 분리 집계 0건** — 정규화 후 집계 | 분리 품목 수 107 → 0 |
| P3 | **승인 절차의 시스템화** — 책임자 확정 전에는 정산·생산 단계로 넘어가지 않음 | 미승인 수주의 후속 단계 전달 0건 |
| P4 | **변경 이력 100% 기록** — 처리자·일시·변경 전/후 값 | 감사 로그 누락 0건 |
| P5 | **확장 기반 마련** — 생산·구매·품질·경영지원이 같은 기준정보를 사용 | 공통 품번 마스터 1개 |

├──────────────────────────────────────────────┬────────────────────────────────┤
│ [D] ① 접수 폼 (실시간 정규식 검증)             │ [F] ★ 정규화 전/후 라이브 비교   │

│     오표기 셀 붉은 하이라이트 · 스캔 레이저      │ [H] ⑤ 감사 로그 타임라인          │
├──────────────────────────────────────────────┴────────────────────────────────┤
│ [I] ③ 실시간 집계: 월별 · 담당자별 · 거래처별(체계업체/1차 협력사) · 품목별       │
└───────────────────────────────────────────────────────────────────────────────┘

| 영역 | 기능 | 세부 동작 |
| :---: | :--- | :--- |
| A | 사내 시스템 지도 | 5개 부서 노드. 활성 노드 `[영업: 수주·납품 관리]`에 펄스 글로우, 나머지는 `Phase 2~5` 잠금 배지 |
| B | 5대 동작 파이프라인 | 단계 클릭/작업 수행 시 진행 바가 채워지고 단계 배지(대기→진행→완료)가 스프링 애니메이션으로 전환 |
| C | KPI | 접수 건수, 검증 이슈 수, **분리 품목 수(원본 표기 기준 vs 기준정보 기준)**, 승인 대기 건수 |
| D | ① 접수 | 단건 입력 폼 + 엑셀(CSV) 업로드 + 샘플 데이터 재로드. 품번 입력 중 정규식 실시간 판정(✓ 초록 / ⚠ 주황 교정 추천 툴팁) |
| E | ② 검증 | 각 행의 원본값·정규화값·검증 상태 표시. 오류 셀 붉은 하이라이트 + Shake. `⚡ 기준정보 일괄 정규화` 클릭 시 스캔 레이저가 지나가며 셀이 플립 전환 |
| F | ③ 집계 비교 (킬러 기능) | 기준 미적용: 막대 2개(90 / 57) → 정규화 후: 막대 1개(147)로 병합 + 카운트업 |
| G | ④ 승인 | 책임자 권한에서만 활성. 검증 통과 건 일괄 승인 / 선택 건 반려(사유 필수). 승인 시 파티클 + 토스트 |
| H | ⑤ 기록 | 처리자 · 일시(초 단위) · 변경 상세(`KJH2201 ➔ KJ-H2201`) 타임라인 슬라이드 인 |
| I | ③ 집계 탭 | 월별 / 담당자별 / 거래처별 / 품목별 차트. 정규화 전·후 토글 |
| 패널 | 기준정보 마스터 | 품번 12종·발주처 8곳 열람·검색. 책임자는 품번 추가 가능(정규식 검증) |

## 5. 처리 규칙 (Rules)

### 5-1. 계산 규칙 (집계)

1. **정규화 → 집계 순서 고정**: 모든 집계는 `part_no`·`order_date`·`customer_code`·`unit`의 **정규화 변환값** 기준으로만 합산한다. 원본값(`raw_*`)은 "기준 미적용" 비교 화면에서만 사용한다.
2. **품목별 합계** = `SUM(qty) GROUP BY part_no` (단, `validation_status ∈ {VALID}` 이고 `approval_status ≠ REJECTED`).
3. **월별 합계** = `SUM(qty) GROUP BY substr(order_date, 1, 7)` → 예: `2026-01`, `2026-02`.
4. **거래처별 합계** = `SUM(qty) GROUP BY customer_code`, 다시 `customer_type`(체계업체 / 1차 협력사)으로 소계.
5. **담당자별 합계** = `SUM(qty) GROUP BY received_by`.
6. **분리 품목 수** = `COUNT(DISTINCT raw_part_no) − COUNT(DISTINCT part_no)` → 대표 사례 기준 `2 − 1 = 1`, 12개월 실데이터 기준 `107 → 0` 목표.
7. **검증 사례 계산**: `KJ-H2201` = 40 + 35 + 50 + 22 = **147** (정규화 전에는 `KJ-H2201` 40+50=**90**, `KJH2201` 35+22=**57**).
8. 단위가 다른 품목(`개(EA)` vs `세트(SET)`)은 수량을 서로 더하지 않는다 — 품목별 합계는 같은 품번(=같은 표준 단위) 안에서만 계산한다.

### 5-2. 조건 규칙 (검증 · 자동 치환)

| 규칙 ID | 대상 | 조건 | 판정 | 자동 치환(Auto-Normalize) |
| :---: | :--- | :--- | :---: | :--- |
| V-01 | 품번 | `^KJ-[A-Z]\d{4}$` 일치 **그리고** 품번 마스터에 존재 | ✅ VALID | — |

- `⚡ 일괄 정규화`는 **FIXABLE 항목만** 치환하며, 치환 1건마다 `audit_logs`에 `NORMALIZE` 로그 1건을 남긴다.
